# v3.21 PRD · 失物招领闭环 + 体验优化

> 产品：四川文轩职业学院遂宁校区地图 App
> 版本基线：v3.20（Cloudflare Pages + Worker + D1）
> 语言：简体中文 · 前置技术栈：Vite/静态前端 + Worker API + D1
> 处理人：许清楚（产品经理）

## 1. 产品目标

把失物招领从"答对即 done、靠系统兜底清理"的被动流程，升级为**用户可主动掌控、状态清晰可归档**的闭环；同时补足地图侧的高频定位与数据反馈能力，降低新用户找地点、纠错的门槛。一句话：**"让每一次认领都能自己画上句号，让每一次问路都能一步到位、有错可说"。**

## 2. 用户故事

- 作为**认领人或发布者**，我要在认领成功后**点一下"完成认领"**就立刻把帖子归档，这样不必干等 5 分钟自动清理、也不怕误认领后错过确认窗口。
- 作为**查看"我的"列表的用户**，我要在**进行中 / 已完成**两个 tab 里分开看自己的帖子，这样不再被混杂状态淹没，能一眼知道自己还有哪些没处理完。
- 作为**发布者**，当我要撤回一条**已被认领完成**的帖子时，我希望系统**自动通知认领人**，这样对方不会茫然的找不到"为什么帖子没了"。
- 作为**新来校或路痴的用户**，我要在地图上**点食堂/快递/运动场/医务室的快捷 chip**就瞬间飞到对应地点，这样不用开搜索翻找分类。
- 作为**发现某地点信息有误用户**，我要能在详情卡**一键"报错"**并提交表单，这样管理员能收到反馈及时修正坐标/信息/营业状态。
- 作为**想把地点分享给同学的用户**，我要能通过系统分享面板**把带 poi 参数的链接发给对方**，这样对方点开就直达该地点的详情卡。

## 3. 需求池

### P0（必做）

- [ ] **P0-1 · 主动"完成认领"按钮**：认领成功进入 `done` 状态时，立即在认领人 AND 发布者两端各给一个"✅ 完成认领"按钮（取代"等待自动清理"）。点击即调 worker 接口确认完成归档：状态保持 `done`，清除/隐藏"将在 N 分钟后自动清理"倒计时文案，改为"✅ 已由你确认完成"。是否保留 5 分钟兜底清理可二选一（见待确认问题 A）。
- [ ] **P0-2 · "我的"二级 tab 拆分为 进行中 / 已完成**：把当前"我的"平铺列表改为两个 sub-tab——进行中(`open`) / 已完成(`done`)，各自显示数量计数，默认落点"进行中"。
- [ ] **P0-5 · 热门地点快捷 chips**：地图底部（下方 tab 栏上方）加一行横向可滚动的玻璃质感快捷 chips，至少含：食堂、快递站、运动场、医务室。点击 → 地图飞向对应 POI 并弹详情卡。POI 匹配复用 `campus-data.js` 里 `BUILDINGS` 的 `id`/`name` 字段建立映射（需二次确认选中哪四个具体 POI，见待确认 E）。

### P1（应做）

- [ ] **P1-3 · 撤回已完成帖子时通知认领人**：当用户撤回一条 `done`(已被认领完成) 帖子时，向 `claims` 中的认领人发送一条系统私信："你认领的「xx」已被发布者撤回"。复用聊天系统通知机制写入 `system:true` 特殊消息。前提：仅 `done`(有人认领)被撤回才通知；`open`(无人认领)被撤回**不发**通知。
- [ ] **P1-6 · 地点详情 Web Share API 分享**：详情卡片右上角加"分享"按钮，调用 `navigator.share({title, text, url})`，不支持的浏览器降级为"复制链接"提示。链接形如 `https://wenxuan-campus-map.pages.dev/?poi=<POI_id>`；App 启动解析 query string 自动飞向该 POI 并打开详情卡。
- [ ] **P1-7 · 地点详情"报错"入口 + 后端反馈落库**：详情卡底部加"📝 数据报错"链接 → 弹出简单表单：问题类型（地点关闭 / 坐标错误 / 信息错误 / 其他）+ 备注(≤100 字)。提交调用**新建**接口 `api/pois/:id/feedback`，后端写入 D1 **新表 `poi_feedback`**（需在 `worker/schema.sql` 追加建表语句并迁移），成功后 toast 提示。

## 4. UI 设计稿（文字描述）

**组件 A · "完成认领"按钮（P0-1）**
- 位置：`done` 状态帖详情卡内原"等待自动清理"文案区附近。
- 样式：主按钮 `<button class="btn-primary lf-finish-btn">✅ 完成认领</button>`。
- 角色区分：认领人=发布者两侧都显示；非相关他人不显示。
- 交互态：点击 → 按钮转 loading"确认中…"→ worker 返回 → 文案收敛为"✅ 已由你确认完成"，隐藏倒计时"将在 N 分钟后自动清理"。
- 失败态：toast 报错提示，按钮恢复可点。

**组件 B · "我的"二级 tab（P0-2）**
- 位置：失物招领"我的" tab 内容区顶部。
- 结构：横排两个开关式 sub-tab："进行中 (N)" / "已完成 (N)"，中间 1px 分隔；激活项高亮下划线/底色。
- 行为：默认选中"进行中"；切换只过滤当前用户自身帖子并按对应状态渲染列表（复用现有排序规则：进行中在前、已完成用降级样式）。

**组件 C · 热门地点快捷 chips（P0-5）**
- 位置：地图视图底部、底层 tab 栏之上，悬浮一条横向胶囊带。
- 样式：液态玻璃质感背景（半透明磨砂 + 细边框），chip 呈圆角胶囊，内容=emoji 图标 + 文案（🍴 食堂 / 📦 快递站 / ⚽ 运动场 / ⛑ 医务室）。
- 交互：整条支持横向滚动以容纳更多；点击 chip → 地图 `flyTo` 该 POI 并打开其详情卡；当前已在详情态时关闭详情再飞。图例/其它浮动控件收起时自动让位。

**组件 D · 详情卡"分享"按钮（P1-6）**
- 位置：地点详情卡片头部右上角（标题行最右）。
- 图标：↗/🔗 分享，轻量 icon button。
- 交互：点按 → 尝试 `navigator.share`；失败(`AbortError` 取消/不支持) → 降级"已复制链接" toast 并把 `?poi=<id>` 写入剪贴板。

**组件 E · "报错"入口 + 表单（P1-7）**
- 入口：地点详情卡底部一行小字链接"📝 数据报错"。
- 表单（弹层/bottom-sheet）：问题类型 4 选 1 单选（地点关闭 / 坐标错误 / 信息错误 / 其他）；备注 textarea 上限 100 字带计数；提交按钮。
- 提交：POST → toast"✅ 感谢反馈，我们会尽快核实"，关闭弹层。

**组件 F · done 卡片降级样式（P2-4）**
- 卡片：`filter: grayscale(...)`、`opacity .55`；右上角叠加"✅"大角标（绝对定位大圆角标）。
- 暗色模式：分别定义淡色/暗色两套 filter 与角标颜色，保证辨识度。

## 5. 决策记录（原"待确认问题"已由 team-lead 决策）✅

- **A（P0-1）已决策**：取消 `autoDeleteAt` 5 分钟兜底清理。数据结构二选一（以最小改动为准，交付前定夺）：①新增 `confirmedAt` 时间戳字段记录"人确完成"，或 ②直接清空/移除 `autoDeleteAt`。
- **B（P0-2）已决策**：`pending` 已废弃，统一二分 → 「进行中」=`open`，「已完成」=`done`（不再含 pending）。
- **C（P1-3）已决策**：系统消息 = 普通气泡样式 + 头部加 🛎️ 小 icon 提示"来自系统"，且**不允许用户删除**（须后端/前端双重兜底）。
- **D（P1-6/P1-7）已决策**：`?poi=<id>` 直链**需新增解析**——覆盖 PWA 冷启动（首次加载即解析）与"已打开页面收到同窗口分享链接跳转"两条路径；解析逻辑落点由架构师定。
- **E（P0-5/P1-6/P1-7）已决策**：热门 chips 从 `BUILDINGS` 检索落地 4 个具体 POI：**食堂 / 快递站 / 运动场 / 医务室**。**分享、报错均无需登录**即可用；对"详情类 POI"(带 info)开放。
